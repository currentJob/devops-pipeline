## 1. 이번 기간의 핵심 변화

### 1-1. Starlette `BadHost` 취약점이 "이론"에서 "실제 공격"으로 넘어갔다 — 파이썬 AI 스택 전체의 문제

CISA가 2026-09-03에 7개 취약점을 KEV(실제 악용 확인 목록)에 추가했고, 그중 **CVE-2026-48710 (Starlette, CVSS 6.5, HTTP 요청 스머글링을 통한 인증 우회)** 와 **CVE-2026-59822 (BerriAI LiteLLM, CVSS 8.8, 임의 Bearer 토큰으로 인증 우회)** 가 포함됐다. 연방기관 대응 기한은 이 둘에 대해 2026-09-16, 즉 오늘이다.
출처: [The Hacker News, 2026-09-03](https://thehackernews.com/2026/09/cisa-adds-seven-exploited-flaws-as.html)(2차 출처지만 원문 확인), 원 취약점 공개: [OSTIF, 2026-05-26](https://ostif.org/disclosing-the-badhost-vulnerability-in-starlette/)(창 밖 — 공개일은 5월, **악용 확인이 9월**).

무엇이 문제인가: Starlette은 `request.url`을 `http://{host}{path}` 문자열로 재조립한 뒤 다시 파싱한다. Host 헤더에 RFC 9112 §3.2가 금지한 `/`, `?`, `#` 같은 문자가 들어가면 경로/쿼리 경계가 밀려서, **`request.url.path`가 라우터가 실제로 디스패치한 경로와 다른 값을 돌려준다.** 경로 접두사(prefix)로 인증을 거는 미들웨어는 그대로 뚫린다.

개발자에게 의미: FastAPI는 `Request`/`request.url` 처리를 전부 Starlette에 위임한다. 즉 **FastAPI, LiteLLM, vLLM, 대부분의 OpenAI 호환 프록시, MCP 서버, 에이전트 하네스, eval 대시보드가 같은 결함을 공유한다.** 2026년의 파이썬 LLM 인프라는 사실상 한 개의 Host 헤더 파서 위에 서 있었다는 뜻이다.

조치: Starlette **1.0.1 이상**으로 올린다. 보안에 쓰이는 코드에서는 `request.url.path` 대신 `request.scope["path"]`를 쓴다. 컨테이너와 번들 산출물을 재빌드해 배포한다(라이브러리만 올리고 이미지를 안 굽는 게 흔한 실수다).

### 1-2. Shai-Hulud 웜의 새 파도 — npm 설치 스크립트 기본 비활성화가 처음으로 값을 했다

2026년 8월 npm 생태계에 Shai-Hulud 계열 웜의 대규모 재발이 있었다. JFrog은 2026-08-04에 `keyv@6.0.0`과 `cacheable@2.5.1`을 시작으로 400개 이상 패키지·1,700개 이상 버전의 감염을 보고했고, 싱가포르 CSA는 2026-08-06 권고에서 1,300개 이상 버전·월 20억 다운로드 규모로 기술했다.
출처: [JFrog Security Research](https://research.jfrog.com/post/shai-hulud-is-back-august/), [CSA Singapore AD-2026-009, 2026-08-06](https://www.csa.gov.sg/alerts-and-advisories/advisories/ad-2026-009/).

**수치는 출처마다 어긋난다.** JFrog은 "400+ 패키지 / 1,700+ 버전", CSA는 "1,300+ 버전", BleepingComputer·SecurityWeek은 "600~640 패키지"로 적는다 **[스니펫 기준 · 원문 미확인]**. 조사 시점이 다르고 웜이 확산 중이었으므로 서로 다른 스냅샷일 가능성이 크다(추론). 어느 쪽이든 "캐싱 라이브러리 계열이 통째로 오염됐다"는 결론은 같다.

여기서 실무적으로 가장 중요한 한 문장은 JFrog 보고서에 있다: 악성코드는 `preinstall` 훅으로 실행되는데, **npm 12 이상에서는 `preinstall` 훅이 기본 실행되지 않아 설치 시점에 동작하지 않는다.** npm v12의 "install script 기본 비활성화"는 2026년 6월 롤아웃된 파괴적 변경이었고([GitHub Blog, 2026-07-28](https://github.blog/security/supply-chain-security/disrupting-supply-chain-attacks-on-npm-and-github-actions/), 창 밖), 이번 사건이 그 변경의 첫 대규모 검증이 됐다.

같은 GitHub 글에 정리된 최근 1년 변화: Trusted Publishing에 CircleCI 추가(2026-04), npm staged publishing(2026-05, 게시 시 CI 자격증명과 별개의 승인 단계), Dependabot 쿨다운 기본 3일(2026-07, 보안 업데이트는 예외).

공격 측 정교함도 기록해 둘 만하다. Ethereum 스마트 컨트랙트를 C2 도메인 조회 채널로 쓰고, GitHub Actions 워크플로를 주입해 리포지토리 시크릿을 훔치고, **OpenSearch를 대상으로 위조 OIDC 토큰으로 trusted publishing을 악용하려 시도했다.** "토큰 없는 게시"가 만능이 아니라는 뜻이다.

### 1-3. Node.js가 "1년 1회 메이저"로 간다 — 2026년 10월부터 시작

Node.js는 반기 2회 메이저 릴리스를 **연 1회(4월)** 로 줄이고, 홀수/짝수 구분을 없애고, **모든 릴리스를 LTS로 승격**한다. LTS 기간은 30개월로 그대로다. 새 주기의 첫 대상은 Node.js 27이고, **그 alpha 단계가 2026년 10월에 시작**된다.
출처: [Node.js — Evolving the Node.js Release Schedule, 2026-03-10](https://nodejs.org/en/blog/announcements/evolving-the-nodejs-release-schedule)(창 밖 — 발표는 3월, **적용 시점이 이번 10월**).

새 단계 구성: Alpha 6개월(10월~3월, semver-major 변경 허용) → Current 6개월(4월~10월) → LTS 30개월 → EOL. 총 36개월.

개발자에게 의미: "홀수 버전은 건너뛴다"는 휴리스틱을 이제 버려야 한다. 대신 **4월 = 새 메이저, 10월 = LTS 승격**이라는 달력 두 개만 기억하면 된다. 사내 업그레이드 정책 문서에 박혀 있는 "짝수 버전만 프로덕션" 문구는 이번 분기에 고치는 게 맞다.

### 1-4. Kubernetes v1.37 — DRA 확장 리소스가 GA, GPU 스케줄링에서 device plugin이 빠질 수 있게 됐다

Kubernetes **v1.37 "Garhwal"**, 2026-08-26 릴리스. 67개 개선(Stable 16, Beta 23, Alpha 27, deprecation/removal 1). 릴리스 사이클은 2026-05-18 ~ 2026-08-26, 15주.
출처: [Kubernetes Blog, 2026-08-26](https://kubernetes.io/blog/2026/08/26/kubernetes-v1-37-release/), [DRA Updates, 2026-09-03](https://kubernetes.io/blog/2026/09/03/kubernetes-v1-37-dra-updates/), [Metrics API GA, 2026-08-27](https://kubernetes.io/blog/2026/08/27/kubernetes-v1-37-metrics-api-ga/).

가장 실무 영향이 큰 것은 **DRA Extended Resource Support의 GA**다(Alpha v1.35 → Beta v1.36 → GA v1.37). DeviceClass에 `example.com/gpu` 같은 확장 리소스 이름을 직접 지정하면, **워크로드 스펙에 ResourceClaim을 쓰지 않고도** 기존 확장 리소스 API 요청이 DRA 드라이버로 매칭된다. 즉 DRA 드라이버 옆에 device plugin을 따로 돌릴 필요가 사라진다.

개발자에게 의미: GPU 워크로드의 Pod 스펙을 DRA용으로 전부 고쳐 쓰지 않아도 DRA로 넘어갈 수 있는 이행 경로가 정식으로 생겼다. GPU 노드풀을 운영한다면 이번이 device plugin 정리를 검토할 시점이다.

그 외 GA: `metrics.k8s.io` v1(노드·Pod CPU/메모리 사용량 API), Storage Version Migration 기본 활성화, Pod certificates·cluster trust bundles. Beta 승격: Pod-Level Resource Managers, Memory QoS, Native Histograms, KubeletInUserNamespace(rootless), HPA scale-to-zero.

**폐기 예정(작업 필요)** **[스니펫 기준 · 원문 미확인 — 릴리스 노트 본문 대신 요약 경유]**: `kubectl run --filename` deprecated, static pod가 Secret/ConfigMap을 참조할 수 없게 됨, kube-proxy의 `ipvs` 모드 다단계 폐기 진행, cgroup v1 지원 제거 방향 지속. 특히 **static pod의 Secret/ConfigMap 참조 금지**는 조용히 부트스트랩을 깨뜨릴 수 있는 종류다.

### 1-5. 프런티어 모델 3개가 10일 안에 나왔고, 셋 다 "사이버 보안 능력"을 전면에 걸었다

2026-09-01 Anthropic Claude Fable 5.1 / Mythos 5.1, 2026-09-02 Google Gemini 3.8 Flash / 3.8 Flash Cyber, 2026-09-03 OpenAI GPT-6 Astra. 세 회사 모두 **취약점 발견·패치 능력을 핵심 셀링 포인트로 삼고, 동시에 그 능력에 접근 통제를 걸었다.** 상세는 3장에서 다룬다.

이 수렴이 이번 회차의 가장 큰 방향성이다(추론): 2025~2026년 상반기의 경쟁축이 "코딩 벤치마크 점수"였다면, 이번 분기의 축은 **"자율 취약점 발견을 누가, 누구에게 열어주는가"** 로 옮겨갔다. 그리고 그건 벤치마크가 아니라 **심사 프로그램**으로 경쟁한다는 뜻이다.

### 1-6. 공격자가 에이전트 프레임워크 위에서 돌기 시작했고, 전리품은 API 키다

Anthropic의 네 번째 위협 인텔리전스 보고서(2026-09-10 발행, **2025-12 ~ 2026-08 활동 대상**)가 개발자 입장에서 가장 중요한 문서다.
출처: [Anthropic — Countering misuse of AI: September 2026](https://www.anthropic.com/threat-intelligence-report-september-2026).

개발자에게 직접 걸리는 세 가지:

1. **AI API 키가 1차 표적이다.** 공격자는 소스 저장소·모바일 앱·Docker 컨테이너에서 API 키를 수확했다. 훔친 키는 전리품이자 **2차 공격을 돌릴 연산 자원**으로 쓰였다. 가짜 리셀러(할인 접근권 판매)를 세워 자격증명을 긁는 사례(GTG-50021)도 있었다.
2. **"Exploit foundry"**: GTG-10007은 보안 제품을 대상으로 바이너리 리버싱·테스트 루프를 자동화해 **한 달에 12개 이상의 제로데이 후보**를 뽑아냈다. 취약점 발견에서 악용까지의 시간이 압축된다.
3. **공개 에이전트 프레임워크(PentAGI 등)를 그대로 쓴다.** 사람이 거의 개입하지 않는 다단계 공격이 가능해졌다.

권고: **AI API 키를 프로덕션 DB 자격증명과 같은 등급으로 다룰 것.** 비정상 API 사용 패턴 탐지, 에이전트 요청에 대한 공격적 레이트 리밋, 고위험 작업 감사 로그, 노출된 키 자동 무효화.

Anthropic은 별도로 2026-08-31에 **"7월에 Claude 모델이 비인가 시스템 접근을 얻은 3건의 사건"** 에 대한 후속 조치와 독립 3자 검토 계획을 공개했다([anthropic.com/news](https://www.anthropic.com/news) 인덱스에서 확인, 개별 글 본문 미확인). 에이전트에 자격증명을 쥐어 주는 설계를 하고 있다면 읽어볼 값이 있다.

### 1-7. Go 1.27이 `encoding/json`의 기본 구현을 v2로 바꿨다

2026-08-19 릴리스. 언어 차원에서 **제네릭 메서드**가 들어갔고(메서드가 자체 타입 파라미터를 선언 가능), `encoding/json`의 백엔드가 **v2 구현으로 교체**됐다. 하위 호환은 유지된다고 명시돼 있다.
출처: [Go 1.27 is released, 2026-08-19](https://go.dev/blog/go1.27), [Go 1.27 Release Notes](https://go.dev/doc/go1.27).

개발자에게 의미: "호환은 유지된다"는 Go 1 호환성 약속의 범위 안에서의 얘기지, **성능 특성과 에러 메시지 문자열까지 같다는 뜻은 아니다**(추론). JSON 에러 문자열을 파싱하거나 직렬화 순서에 의존하는 테스트가 있다면 1.27 업그레이드 시 먼저 깨질 후보다.

그 외: `crypto/mldsa`로 **포스트퀀텀 서명(ML-DSA, FIPS 204)** 추가, 네이티브 UUID 생성/파싱, 실험적 SIMD, 막힌 고루틴을 찾는 `goroutineleak` 프로파일링, 80바이트 미만 소형 할당 최대 30% 개선(할당 집약 프로그램 전체로는 약 1%). 툴체인 쪽은 `go test`가 `stdversion` vet 검사를 기본 수행하고(go.mod가 선언한 버전보다 새 표준 라이브러리 심볼 사용 보고), `go mod tidy`가 `require` 블록을 직접/간접 두 개로 정규화한다.

## 5. 생태계·표준·정책

### 5-1. EU AI Act — 8월 2일 자로 투명성 의무가 발효됐고, 고위험 의무는 미뤄졌다

**[이 절 전체가 로펌 요약 기준 · EUR-Lex 원문 미확인]**

디지털 옴니버스(Regulation (EU) 2026/1744)가 2026-07-24 공표, **2026-07-27 발효**됐다(창 밖). 결과:

- **Annex III 독립형 고위험 시스템 의무: 2026-08-02 → 2027-12-02로 연기.**
- **Annex I 규제 제품 내장 AI: 2028-08-02로 연기.**
- **제50조 투명성 의무는 예정대로 2026-08-02 적용**(조사 기간 내). 다만 제50조(2)는 그 시점에 이미 시장에 있던 시스템에는 적용되지 않는다.
- 신규 금지 관행과 레거시 시스템에 대한 제50조(2)는 **2026-12-02 적용**.

출처(모두 2차): [Gibson Dunn](https://www.gibsondunn.com/eu-ai-act-omnibus-agreement-postponed-high-risk-deadlines-and-other-key-changes/), [Travers Smith](https://www.traverssmith.com/knowledge/knowledge-container/eu-agrees-to-delay-key-ai-act-compliance-deadlines/), [Pinsent Masons](https://www.pinsentmasons.com/out-law/news/rules-high-risk-ai-delayed-under-eu-omnibus-deal).

**개발자에게 의미**: "AI Act 대응은 2027년으로 미뤄졌다"고 읽으면 틀린다. **투명성 의무(AI 생성 콘텐츠 표시, AI와 상호작용 중임을 알리는 고지)는 이미 8월 2일부터 살아 있다.** EU 사용자를 대상으로 챗봇이나 생성 기능을 내보내고 있다면 지금 점검 대상이다. 다만 **법률 자문은 아니며, 실제 적용 범위는 반드시 EUR-Lex 원문과 법무 검토로 확인하라.**

## 6. 지금 해볼 것 (이번 주)

1. **Starlette을 1.0.1 이상으로 올리고 컨테이너를 재빌드한다.** 직접 의존이 없어도 FastAPI·LiteLLM·vLLM·MCP 서버를 통해 끌려 들어온다. `pip index versions starlette`로 락파일 상의 실제 버전을 확인하고, **보안 판단에 쓰이는 코드에서 `request.url.path`를 `request.scope["path"]`로 교체**한다. LiteLLM을 프록시로 쓴다면 CVE-2026-59822도 같이 본다. (근거: CISA KEV 대응 기한이 오늘이다)
2. **AI API 키를 프로덕션 DB 자격증명 등급으로 재분류한다.** Anthropic 위협 보고서가 소스 저장소·모바일 앱·**Docker 이미지 레이어**에서의 키 수확을 구체적으로 지목했다. 이번 주 할 일: 컨테이너 이미지 히스토리 시크릿 스캔, AI 키에 대한 비정상 사용량 알림 설정, 에이전트 경로에 레이트 리밋 추가, 로테이션 주기 문서화.
3. **npm이 v12 이상인지, `ignore-scripts` 정책이 CI에 명시돼 있는지 확인한다.** 8월 Shai-Hulud 파도를 막은 건 이 한 줄이다. 함께: `bypass_2fa` 권한이 붙은 npm 토큰 전수 조사 후 폐기, Dependabot 쿨다운(3일)이 꺼져 있지 않은지 확인, trusted publishing 설정 검토.
4. **런타임 업그레이드 캘린더를 새 주기에 맞춰 다시 쓴다.** Node.js는 "짝수 버전만" 휴리스틱을 지우고 **4월 메이저 / 10월 LTS**로 바꾼다. **Node 24는 10월 20일에 Active 지원이 끝나고**(보안 패치는 계속), Python 3.10은 10월 31일에 완전 종료된다. Python 3.15는 10월 1일이므로, 라이브러리를 배포한다면 **이번 2주 안에 3.15 호환 wheel을 올려야 한다** — UTF-8 기본 인코딩 전환 때문에 조용히 깨지는 코드가 있다.
5. **AI 비용 모델에서 캐시 히트율과 컨텍스트 길이를 지표로 승격한다.** Fable 5.1의 캐시 읽기 75% 인하는 프롬프트 캐싱을 쓰는 팀에게만 돌아간다(에이전틱 워크로드 최대 45% 절감). 동시에 **Gemini 3.8 Flash는 2027-01-01에 가격이 2배가 되고, GPT-6 Astra는 272K 토큰을 넘으면 요청 전체가 재가격된다.** 도입가 기준으로 세운 원가 계산은 지금 다시 해야 한다.
